## 这轮到底解决了什么

可以把 Workflow 想成一段很长的游戏流程。

### 1. Checkpoint 是游戏存档

Checkpoint 会记录：

- 运行到了哪个节点
- 哪些节点已经完成
- 哪些节点还在排队
- 当前是哪次尝试
- 外部数据放在哪里
- 已执行副作用的幂等键
- 有没有正在等待或已经完成的审批

它不保存模型输出、Context、Memory、Artifact 或 secret 的正文，只保存引用，避免存档变成敏感数据仓库。

### 2. CheckpointStore 是带门禁的存档库

保存、读取、列出和删除存档都必须先经过授权。

授权策略可以缩小访问范围，但不能偷偷改掉：

- Run
- Workflow
- 图版本
- Checkpoint 身份
- sequence
- previous checkpoint

所以即使底层 Store 本身很简单，也不能绕开权限边界访问它。

### 3. `latest_checkpoint_ref` 是“官方存档书签”

仅仅把 Checkpoint 写进 Store，还不算正式存档。

正式提交流程是：

```text
写入 Checkpoint
→ CAS 更新 WorkflowRun.latest_checkpoint_ref
→ 发布 checkpoint.saved
```

只有 Run 指向的 Checkpoint 才是恢复起点。

如果写入 Store 后、更新 Run 前崩溃，这条记录只是 orphan，恢复不会误用它。
